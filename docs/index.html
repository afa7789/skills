Features first.
Every task proves itself.

FDD turns a brief or an existing repo into a canonical feature graph, then a task DAG where every task carries one binary check. An external loop runs the tasks. Exit 0 closes a task; nothing else does.

Works with Claude Code, OpenCode, Codex, Hermes, Pi and OMP.

How it flows

Each step reads its reference, writes one file under features/ and commits it before the next.

1

Discover

Existing repos only. Code, docs, tests and history are evidence, not the spec. evidence.yaml

2

Graph

Product behavior, dependencies and acceptance criteria as input → output. Canonical. graph.yaml

3

Gaps

Existing repos only. Audit every feature against the graph, read-only. gaps.yaml

4

Plan

Minimum task set in dagRobin import format. Each task: one check. tasks.yaml

New repo: brief → graph → plan. Existing repo: all four. Full pipeline:

prompt-refiner→fdd→dag-loop→review

The graph is canonical

Features describe what a user observes, not which folder holds the code. Dependencies say what must work first; independent features become parallel tasks.

The code never rewrites the graph. If the graph is wrong, the worker stops and proposes a spec change.

One task, one check

Every task names one command. dagRobin verify <id> runs it; exit 0 is the only way to close the task. Checks run in a fresh worktree, so they install their own deps.

- id: f002-login
  title: Log in with email and password
  deps: [f001-signup]
  files: [src/auth/login.ts]
  tags: [feature:F-002, phase:feature]
  metadata:
    long-description: |
      smoke: POST /login valid → 200 + cookie
      harden later: wrong password → 401
    check: npm ci -s && npm run smoke:login
PhaseThe check proves
featureBuild, then the main action responds: CLI prints, route answers, page renders. No unit tests needed.
hardenAfter every feature is Done. Failing test first; the check runs only that test and greps its pass line.
infraSetup works, e.g. lint passes with zero warnings.

Rounds of 25 or fewer

A round is the set of tasks not yet archived. Feature rounds come first, split by dependency layer. Harden rounds follow, one task per business rule or edge case. When a round is done: dagRobin archive, write the next, import, check.

Illustrative example: a 40-feature project.

The loop lives outside the model

dag-loop is a bash driver. Per task, one git worktree and one headless agent run:

claim→worktree→agent commits→check→squash-merge→verify on main→Done

A failed check retries from the new HEAD with the failure output in the prompt. Out of retries → Blocked, with the reason in .git/dag-loop.log. Tasks with disjoint files run in parallel with --slots N.

ExitMeaning
0All tasks Done.
3Nothing ready: the rest are Blocked or wait on deps.
1Precondition, dagRobin, host crash or timeout.

Hard rules

  • The graph is canonical. Never change it to match the code.
  • A task without a check is not a task. Exit 0 means done.
  • Every acceptance criterion maps to a feature smoke check or a later harden task.
  • check-dag.sh exits 0 before any work starts.
  • Task ids are never reused. Never import --replace: it wipes archived rounds.
