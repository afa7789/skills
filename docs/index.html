Features first.
Every quest proves itself.

FDD is a skill for coding agents. It turns a brief or an existing repo into a feature graph, then into tasks that each carry one shell command. The command exits 0: the task is done. Nothing else closes it.

  1. Features first. Every feature works before any hardening starts.
  2. One check per task. Exit 0 is the only proof.
  3. The loop lives outside the model. A bash driver runs the agents; no agent can talk itself into “done”.

Follow one feature

From one sentence to one merged commit. The same feature, F-002, in each file it passes through.

  1. 1 · Brief

    You write it, or prompt-refiner sharpens it.

    Users log in with email and password.
A wrong password gets a 401.

  2. 2 · features/graph.yaml

    fdd writes behavior a user can observe. This file is the spec; the code never overrides it.

    - id: F-002
  name: Log in with email and password
  dependencies: [F-001]
  acceptance_criteria:
    - POST /login valid → 200 + session cookie
    - POST /login wrong password → 401

  3. 3 · features/tasks.yaml

    fdd plans the minimum tasks. Each one gets one check. Rules and edge cases wait for a harden round.

    - id: f002-login
  deps: [f001-signup]
  tags: [feature:F-002, phase:feature]
  metadata:
    long-description: |
      smoke: POST /login valid → 200 + cookie
      harden later: wrong password → 401
    check: npm ci -s && npm run smoke:login

  4. 4 · .git/dag-loop.log

    dag-loop gives the task to an agent in its own git worktree, runs the check, merges, then verifies on main.

    f002-login attempt 1/3 by dagloop-claude-1
f002-login merged as 4e1c2a7
f002-login done

  5. 5 · git log

    One feature, one commit (or one batch commit). The 401 rule returns later as an optional harden probe — or test if the project uses them.

    4e1c2a7 feat(F-002): Log in with email and password
later: test(F-002): wrong password → 401

Rounds of 25 or fewer

Tasks load in rounds of 25 or fewer. Every task has one phase:

PhaseIts check proves
featureBuild, then the main action responds. No tests.
hardenOptional: one rule or edge case (direct probe by default; test only if the project uses them).
infraSetup works, e.g. lint passes.

Existing repo

Two read-only steps run before the plan. Discover writes evidence.yaml: what the code, tests, docs and history claim. Gaps writes gaps.yaml: every feature audited against the graph. Each finding lands in a phase.

FindingLands in
BLOCKER INCORRECT INCOMPLETEa feature round
TEST_GAPa harden round
DOC_GAP LEGACY IMPROVEMENTa harden round, last

The loop

dag-loop is a bash script, not a prompt. It runs Claude Code, Codex, OpenCode, Pi, OMP, Hermes or Antigravity headless, batching ready tasks into one worktree per slot by default (--batch all|N):

claim→worktree→agent commits→check→squash-merge→verify on main→Done

A failed check retries with its output in the prompt. Out of retries, the task is Blocked with a reason. The script exits 0 when all tasks are done, 3 when nothing is ready, 1 on error.

Rules

  • The graph is canonical. If it is wrong, the worker stops and proposes a spec change.
  • A task without a check is not a task.
  • Every acceptance criterion maps to a feature smoke check or a later harden task.
  • check-dag.sh exits 0 before any work starts.
  • Task ids are never reused. Never import --replace: it wipes archived rounds.

Install

git clone https://github.com/afa7789/skills && cd skills
bash scripts/install-tools.sh          # Rust + dagRobin
bash scripts/sync-skills.sh --status   # dry run
